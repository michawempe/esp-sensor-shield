# Firmware

The Arduino sketch sends the latest sensor values in one JSON packet over USB
Serial at a target rate of 50 Hz (20 ms interval). Acquisition depends on the
sensor: ADC1 samples continuously via DMA, distance measurements run continuously
and are polled, and digital inputs, touch and ADC2 are read for each output packet.
Encoder pulses are counted in hardware. A packet does not necessarily contain a
new measurement from every sensor. Use [PlatformIO](../platformio/README.md) to
build and upload.

## Configuration

Send one JSON object followed by a newline. Each key is a shield port:

```json
{"B1":{"type":"slider","name":"slider1","smoothingMs":100},"A1":{"type":"button"}}
```

This replaces the whole configuration. The reply is
`{"status":"config_applied","persisted":true}` when saving succeeds.
Settings are stored on the ESP and restored on boot. Send `{}` to remove all
configured sensors. The built-in default is also empty. Missing names are
generated by type, such as `slider1`; explicit names must be unique and at most
31 bytes long. Invalid configurations leave the active configuration unchanged.
A `persisted: false` reply with `status: "config_applied"` means the new settings
are active in RAM but were not saved for the next boot.

| Ports | Types | Parameters and defaults |
|---|---|---|
| A1–A6 | `button`, `switch` | No parameters; 0 is active |
| B1–B5 | `slider`, `light`, `magnet` | `inMin: 0`, `inMax: 4095`, `outMin: 0`, `outMax: 1` |
| B1–B5 | `sound` | `inMin: 100`, `inMax: 4095`, `outMin: 0`, `outMax: 1` |
| C1–C4 | `joystick` | `midCutoff: 100`, `edgeCutoff: 0`, `outMin: -1`, `outMax: 1` |
| C1–C4 | `encoder` | `fullRotation: 360`, `modulo: false` |
| C1–C4 | `distance` | `inMin: 30`, `inMax: 600` (mm), `outMin: 0`, `outMax: 1` |
| D1–D4 | `touch` | `threshold: 50000`; 1 when raw > threshold |

At most two distance sensors can run at once. Joystick cutoffs set the center
and edge dead zones in ADC counts around a center of 2048. Encoder scaling
assumes 40 ticks per physical turn; `fullRotation` sets the output per turn,
and `modulo` wraps the output into `[0, fullRotation)` when `fullRotation > 0`.

Slider, light, magnet, sound, joystick and distance accept `smoothingMs` from
0 to 10000 (integer milliseconds, default 0). Zero disables smoothing; try 100
for a steadier response. This is the time constant of a first-order low-pass
filter, not a fixed delay or averaging window. Higher values respond more slowly.
Smoothing affects `value`, not `raw`; distance also uses a five-reading median
filter, including for its `raw` output.

## Output

```json
{"data":{"slider1":{"type":"slider","port":"B1","raw":2048,"value":0.5,"inMin":0,"inMax":4095,"outMin":0,"outMax":1,"smoothingMs":100}}}
```

`value` is the mapped output. Joystick readings have `{ "x": ..., "y": ... }`
for both `raw` and `value`. Light inverts the ADC reading; sound reports the
peak-to-peak level; distance reports filtered millimetres.

Unavailable readings are `null`, with an `error` field where provided. Config
changes and USB backpressure can interrupt output; missed packet slots are
skipped rather than replayed. Output also pauses while a command is arriving and
until 40 ms after its last byte. Input lines may contain at most 8192 bytes
(excluding CR/LF). An unfinished input line times out after one second without
further bytes; send a newline before retrying the command.

## Timing and code changes

The default publish interval is `ILAB_PUBLISH_INTERVAL_MS = 20`. It controls
packet output, not the ADC sample rate or the distance measurement budget.

ADC1 uses DMA for B1–B5 and joystick axes on C1/C2: nominally 16 kHz per active
ADC1 pin when any sound sensor is configured, or 1 kHz without sound. Above five
active ADC1 pins, the per-pin rate drops to keep the total at or below 80 kHz
(rounded down to a multiple of 50 Hz). Sound windows remain nominally 20 ms
(320 samples at 16 kHz). Actual hardware rates can differ slightly.
ADC and sound readings become unavailable after 100 ms without fresh data.
Joysticks on C3/C4 use ADC2 direct reads at the packet rate. Distance uses a
20 ms measurement budget, polls readiness no more often than every 2 ms, and
expires after 100 ms without a result in the normal build.

Add sensor classes in `sensors/` and register them in `config/ConfigManager.h`.
Use `analogSampler` for ADC1 pins; do not mix it with `analogRead()` on ADC1.
ADC2 uses direct reads. Config changes stop DMA before replacing sensors and
restart it after saving to flash. Pin assignments are in
[PortMap.h](ilab_ESP32_S3_Sensor_Shield/PortMap.h).

For Arduino IDE, open the `.ino` in `ilab_ESP32_S3_Sensor_Shield/`. Use core
3.3.7, ArduinoJson 7.4.2 and Pololu VL53L0X 1.3.1. Select ESP32S3 Dev Module,
USB-OTG (TinyUSB), CDC on boot, 8 MB QIO flash at 80 MHz, the
"8M with spiffs (3MB APP/1.5MB SPIFFS)" partition scheme,
PSRAM disabled and 115200 baud for upload and monitor.
